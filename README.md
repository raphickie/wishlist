# ВСРАТЫЙ ВИШЛИСТ 🐈🧗🏄🪁💻

Vite + React + TypeScript + Firebase Firestore, опубликованный на GitHub Pages. Красота спорная, коты настоящие (ну почти).

## Запуск локально

```bash
npm install
npm run dev
```

Клиентская конфигурация Firebase `wishlist-88734` уже записана в `src/firebase.ts`. Никакие `.env` и GitHub Secrets для существующего Firebase-проекта не нужны.

Это обычная публичная конфигурация Firebase Web App: она доступна в браузере по определению. **Защиту данных обеспечивают правила Firestore, а не скрытый API key.** Никогда не помещайте в исходники сервисные аккаунты и приватные ключи.

## Однократная настройка Firebase Console

Зайди в https://console.firebase.google.com/ и выбери проект **wishlist-88734**.

1. **Authentication → Sign-in method → Anonymous** — включить и сохранить. Гостям не нужны email и пароль.
2. **Firestore Database** — создать базу **(default)** (Standard Edition) в режиме production, если ещё не создана.
3. **Firestore Database → Rules** — вставить содержимое файла `firestore.rules` и нажать **Publish**.

Обычные подарки бронируются в Firebase Firestore через коллекцию `reservations`: один документ на подарок, чтобы исключить дубли. Для чая, орехов и бумажных книг установлен флаг `noBooking: true` в `src/gifts.ts`. Их **не нужно бронировать**: карточка всегда отображается во вкладках «Свободно» и «Всё», кнопка заменена надписью «Бронировать не надо. Просто покупай и дари!», и никакие запросы в Firestore при выборе этих подарков не отправляются. Во вкладке «Занято» они не появляются. Старые записи Firestore для них игнорируются.

Для этой функции **не нужны новые правила Firebase** или отдельные коллекции. Файл `firestore.rules` содержит только стандартные правила для обычных броней.

**Важно:** если гость очистит данные браузера или сменит устройство, он может потерять возможность отменить свою анонимную бронь. Администратор при необходимости удаляет документ из Firestore Console. Анонимная авторизация не защищает от намеренного спама — проект рассчитан на небольшой круг знакомых.

## GitHub Pages

Сайт публикуется из `master` автоматически через `.github/workflows/deploy.yml`.

**URL:** https://raphickie.github.io/wishlist/

Нужна настройка **Settings → Pages → Source: GitHub Actions** (уже была сделана). Firebase Hosting не нужен; бесплатный GitHub Pages обслуживает статические файлы.

## Список подарков

Редактируй `src/gifts.ts`: меняй название, бюджет, описание и ссылку. `id` должен быть уникальным; не меняй ID после того, как кто-то уже забронировал подарок.

## Проверка

1. Открой сайт и убедись, что индикатор показывает `CATBASE ONLINE`.
2. Забронируй тестовый подарок.
3. Открой страницу в приватном окне: обычный подарок должен оказаться во вкладке «Занято», и повторно забронировать его нельзя.
4. Вернись в первое окно и отмени свою бронь. Подарок снова появится во вкладке «Свободно».

Если видишь `CATBASE ERROR` или ошибку `Missing or insufficient permissions`, проверь Firestore Rules. Если `auth/operation-not-allowed`, включи Anonymous Authentication.

5. Для чая, орехов и бумажных книг убедись, что видно «Бронировать не надо», а кнопки бронирования нет даже в режиме инкогнито.
